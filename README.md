# Аналіз ефективності жадібного алгоритму і динамічного програмування
### Жадібний алгоритм (find_coins_greedy)
Час виконання: О(m), де m - кількість монетного номіналу. Це викликано простим проходженням по списку монет
Ефективність: В деяких наборах монет може не давати оптимальний результат (наприклад: сума 30, коли набір містить монети 25, 20, 1).

### Динамічне програмування (find_min_coins)
Час виконання: O(n*m), де n - сума розміну, m - кількість номіналів монет. Алгоритм перебирає все суми до n для кожного номіналу.
Ефективність: Гарантовано знаходить мінімальну кількість монет для будь-якої суми.

### Висновки
Жадібний алгоритм
Швидкий і простий.
Підходить для систем, де час відповіді є критичним і номінали монет дозволяють вживати такий підхід (наприклад, стандартний набір для монетників).
Може не бути ефективним, якщо номінали монет вибрано неоптимально для певних сум.

Динамічне програмування
Більш повільний з великими сумами чи набором монет через квадратичну складність.
Завжди дає оптимальний результат з точки зору кількості монет.
Якщо допустима ситуація із затримками в роботі системи, але необхідний точний результат, варто вибирати динамічне програмування. Для систем зі строгими вимогами до швидкості - жадібний алгоритм може бути краще, за умови, що він ефективно працює з даною множиною монет.

### Огляд результатів
- Жадібний алгоритм показав себе досить швидким у порівнянні з динамічним програмуванням на всіх сумах.
- Обидва алгоритми вирішують поставлені задачі, видаючи однакові результати за кількістю монет.
- Час виконання динамічного програмування зростає відносно до зростання суми, що видно на прикладі суми 555.

### Загальні висновки
- Жадібний алгоритм є оптимальним для даного набору монет з точки зору швидкості виконання на великих сумах.
- Динамічне програмування забезпечує точний підхід до вирішення задачі розміну монет, однак його час виконання вищий порівняно з жадібним алгоритмом.
- Вибір алгоритму залежить від вимог до швидкості обробки запитів та точності. У випадках, коли набір монет може утворити неоптимальне рішення жадібним методом, рекомендується використовувати динамічне програмування.
